## 1. スプライトパターンの議論

ユーザーの提案: P0/P1 共通で $00111100（中央寄せ）にすればよいのでは？
Claude の回答: それでは左右対称にならない。
  正しいアプローチ:
    P0（左）: $F0 = 11110000 → スプライトの左4pxを使う
    P1（右）: $0F = 00001111 → スプライトの右4pxを使う

実施: PAD_SPRITE を PAD_SPRITE0=$F0 / PAD_SPRITE1=$0F に分離してコミット。

## 2. P1の右壁からの隙間が大きい問題

スクリーンショットで確認:
  P0: $F0 → 左端 4px 使用 → 左壁から約4px gap
  P1: $0F → 右端 4px 使用 → 右壁から約4px gap

数学的には対称のはずだが、ユーザーは P1 の方が gap が大きいと指摘。

## 3. パドル移動の試み（混乱期）

ユーザーの要望: P0 を右に動かして P1 の gap に合わせてほしい

失敗の原因（後に判明）:
  [誤解①] RESP0 を HBlank 初期に発火している場合、
           NOPを追加してもraw位置は変わらない（固定ゾーン）。
  [誤解②] HMP エンコーディングを「右=正nibble」と勘違いしていた。
           実際は「正nibble（1-7）= LEFT（左移動）」。

試みの履歴:
  変更1: HMP0=$40→$70（コメントで「右7」と書いたが実は LEFT7）
         → P0が左に余計に寄った
  変更2: +1 NOP（無効） + HMP0=$70→$50
         → NOP無効のため HMP 減少分だけ P0 がさらに左へ
  変更3: +1 NOP（無効） + HMP0=$50→$30
         → 同様にさらに左へ

結果: P0 は元の x=4 から x=3 へ、実質的に左に移動してしまっていた。

## 6. HMPエンコーディングの正しい理解（ブレークスルー）

スクリーンショット分析から実証:
  HMP0=$40 → P0 at x=4  → raw=8, 8-4=4 → nibble4=LEFT4
  HMP0=$70 → P0 at x=1  → raw=8, 8-7=1 → nibble7=LEFT7
  HMP1=$10 → P1 at x=150 → raw=151, 151-1=150 → nibble1=LEFT1

TIA HMP エンコーディング（4bitの上位nibble）:
  $0x (0)         = 移動なし
  $1x〜$7x (1-7)  = LEFT 1〜7（x値が減る = 左壁に近づく）
  $8x (8)         = RIGHT 8（2's complement: -8）
  $9x〜$Fx (9-F)  = RIGHT 7〜1（x値が増える = 右壁に近づく）

コード内のコメント「右に4カラークロック」は誤りだった。
正しくは「LEFT 4カラークロック」。

RESP0 の early HBlank 発火で raw 位置 ≈ 8 が確定。
RESP1 の cycle 73 発火で raw 位置 ≈ 151 が確定。

## 7. 最終的な修正

目標: P0 gap = P1 gap = 2px に揃える

P1: sprite_x=150, $0F → active px=154-157, right gap=159-157=2
P0: sprite_x=2 にする → $F0 → active px=2-5, left gap=2

変更: HMP0=$70 → $60
  $60 = LEFT 6: raw=8, 8-6=2 → P0 at x=2, gap=2 ✓
